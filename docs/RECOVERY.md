# Recovery

Close the Remote and all DCR MCP clients first. Keep the Remote directory untouched. If package installation fails before switching, the original should remain unchanged. For a failed switch, inspect the stage and package-backup folders under %LOCALAPPDATA%\DCRManager-state. To restore a complete backup, move current node_modules, package.json and package-lock.json to a separate recovery directory, then copy these three items from the desired package-backup to %LOCALAPPDATA%\DesktopCommander. Do not delete credentials or restore a partial backup blindly. For cache quarantine, the original npm cache is discovered using npm config get cache; move the backed-up directory back only when the original target is absent and no processes use it. Record the original cache path before quarantine. Do not run npm cache clean --force as a default fix.

## v1.2.1
Menu K restores an exclusive DCR cache using its saved metadata, only to an empty child of the current npm _npx directory. Menu T flags backups 30 days old for review without deletion. Menu H reports missing or reused parent PIDs; this is evidence to investigate, not permission to stop a process. Package rollback now attempts all independent reversals and refuses to overwrite existing destinations. If it reports incomplete recovery, leave staging and backup directories intact and recover manually. No operation can guarantee atomicity across external processes, file locks or unexpected power loss.

## v1.3 preview Recovery Center
Open Recovery, press B to cycle and V to request restoring a ready backup. Confirm with Y only after closing DCR Remote/MCP clients. Package restore retains the source and creates a backup of the previous package; cache restore returns the directory to its original empty npm cache path. A completed move consumes the cache-backup directory but preserves its metadata. Retention is review-only (30 days); logical size estimates may be partial. Never delete stage/backup folders after a failed or interrupted switch. Inspect transaction.json and its previous marker, and keep the files for manual recovery. Do not interpret an unclassified stage as proof of a failed rollback. Backups are structurally checked, not cryptographically authenticated.
